# 2026-07-11

## SeekPack (Android, package com.wang.getapk) — ButterKnife → ViewBinding 迁移完成
- 背景：老项目升级，原来处于"半截状态"——`app/build.gradle` 已开启 `viewBinding true`、ButterKnife 依赖已移除，但源码仍用 `import butterknife.*` + `@BindView`，导致编不过。
- 改动文件（6 个 .java + 2 个 layout）：
  - `view/dialog/BaseDialog.java`：改为泛型 `BaseDialog<Builder extends BaseBuilder, B extends ViewBinding>`，用 `getViewBinding()` 替代 `getLayoutId()`；原 `@Nullable`/`@Optional` 的 title 与 neutral/negative/positive 按钮抽成抽象 getter（`getTitleView()/getNeutralButton()/...`），由子类从各自 binding 提供（不存在返回 null）；`@OnClick` 改为 `show()` 内条件式 `setOnClickListener`。
  - 3 个子类 `FileExplorerDialog` / `NumberProgressDialog` / `ProgressDialog`：各自提供 binding 并实现 getter（`FileExplorerDialog` 三类均无，返回 null）。
  - 3 个 Adapter/ViewHolder `AppDelegate` / `StickyDelegate` / `FileAdapter`：改用 `XxxBinding.bind(itemView)`，字段引用改为 `binding.xxx`。
  - `dialog_number_progress.xml`、`dialog_progress.xml`：给 `<include layout_dialog_title>` 补 `android:id="@+id/title"`（ViewBinding 才会生成 include 字段）。
  - 删除 `app/build/` 下陈旧的 `*_ViewBinding.java` 生成文件。
- 注意：当前 3 个 Dialog 实际都无 neutral/positive 按钮（`layout_dialog_button` 布局未被任何 layout 引用），基类逻辑靠 getter 返回 null 兼容。若未来新增使用 `layout_dialog_button` 的 Dialog，需要给该 include 加 id 并实现对应 getter。
- 未做全量编译验证（环境无 Android SDK 36），需用户执行 `./gradlew clean assembleDebug` 确认。

## 修复：FileExplorerDialog.java:125 "需要常量表达式"
- 根因：启用 ViewBinding 后 `R.id.*` 不再是编译期常量，`onMenuItemClick` 里的 `switch (id) { case R.id.confirm: ... case R.id.create: }` 触发 javac 报错"需要常量表达式"。
- 修复：将 `switch/case` 改为 `if (id == R.id.confirm) {...} else if (id == R.id.create) {...}`（`if` 比较允许非 final 的 `R.id`）。
- 预防性加固：补 `import android.content.DialogInterface.OnClickListener;`（原 `new OnClickListener()` 未显式导入嵌套类型，switch 修掉后编译器可能接着在该处报错）。
- 全项目再次扫描确认：已无 `case R.`、无 ButterKnife/Unbinder/R2/@BindView/@OnClick 残留，`build.gradle` 也无 butterknife 依赖。
- 仍建议用户执行 `./gradlew clean assembleDebug` 做最终编译验证（环境无 SDK 36 无法代跑）。
